# 艾松运费管家 V8.5 运行日志实时进度优化 PRD

## 背景

费用计算任务在处理大销售表、拆分客户明细或刷新历史汇总时可能耗时较长。此前 GUI 需要等整个任务结束后才一次性写入运行日志，用户等待时无法判断软件是否仍在工作，也不知道当前处理到哪一步。

V8.5 参考 `head` 设计中运行页的实时进度反馈思路，把运行日志从“结束后的完整回放”调整为“运行中的阶段进度流”。

## 目标

1. 版本号升级为 `V8.5`。
2. 点击 `开始计算` 后继续自动进入 `费用计算 -> 运行`。
3. 任务运行中，日志实时刷新，不等任务全部结束。
4. 日志明确展示：
   - 一共要处理多少销售表。
   - 当前正在处理第几个销售表。
   - 销售表总行数、已处理行数、成功行数、失败行数。
   - 客户每日明细生成进度。
   - 客户历史汇总刷新进度。
5. 运行日志少写具体生成了哪些文件，具体路径继续交给 `结果` 页面展示。

## 范围

### 本次包含

- 核心计算入口新增可选 `progress_callback`，保持 CLI 和旧调用兼容。
- 费用计算、客户每日明细、客户历史汇总阶段按进度向 GUI 发消息。
- GUI worker 将进度消息推入队列。
- GUI 主线程实时追加日志，并继续轮询队列，避免日志卡住。
- 最终摘要降噪，不再在日志里重复输出大量客户文件路径。

### 本次不包含

- 不改变费用计算公式。
- 不改变 Excel 输出字段。
- 不改变结果页文件列表。
- 不新增伪进度条；进度只显示真实已处理数量。
- 不做复杂动画或 pulse dot。

## 进度日志示例

```text
准备运行：共 3 个销售表
正在读取报价表...
报价表读取完成：共 180 条省份价格
销售表 1/3：销售出库单.xlsx
正在计算快递费：共 1200 行
计算快递费：已处理 200/1200 行，成功 198，失败 2
进入阶段：生成客户每日明细
客户每日明细：已完成 20/86 组
进入阶段：批量刷新客户历史汇总
客户历史汇总：已完成 12/35 位客户
全部处理完成：销售表 3/3，成功 3560 行，失败 4 行
```

## 验收标准

1. 主界面显示版本号 `V8.5`。
2. 点击开始计算后自动切到 `费用计算 -> 运行`。
3. 任务未结束时，运行日志已经能看到阶段进度。
4. 日志包含总量和已处理数量。
5. 日志不再刷出每个客户明细文件或历史汇总文件的完整路径。
6. 任务完成后结果页仍能展示生成文件。
7. 现有单元测试通过。
8. `python -m compileall -q app tests` 通过。
9. macOS 打包自检通过。
10. `git diff --check` 通过。
