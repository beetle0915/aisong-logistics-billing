# 艾松运费管家 V8.10 余额上传页面技术方案

## 背景

当前软件已经有 `账户余额` 页面，可以从客户历史汇总表中读取每个客户的累计消费、累计收款、异常扣款和当前余额。后续需要新增一个独立侧边栏页面，用于把指定日期的客户余额数据上传到接收端。

新增页面采用独立 tab，避免影响现有 `费用计算`、`账户余额`、`报价预览`、`拆分账单` 和 `系统设置` 流程。

## 目标

1. 左侧导航新增 `余额上传`。
2. 页面只展示上传所需的最小信息。
3. 用户必须确认上传日期后才能上传。
4. 上传内容只包含每个客户的：
   - 客户名
   - 今日快递费消费
   - 今日余额
   - 状态
5. 上传失败不能影响本地费用计算和历史汇总。

## 数据口径

### 今日快递费消费

指定日期内客户发生的快递费消费。

优先读取客户历史汇总中的 `历史汇总` sheet：

```text
日期 = 上传日期
今日快递总消费
```

如果未来修复历史汇总与快递明细不一致的问题，建议统一改为从最终合并后的 `快递明细` 反算指定日期消费，避免每日明细文件被分批覆盖后造成口径不一致。

### 今日余额

指定日期对应的客户余额。

读取 `历史汇总` sheet 中上传日期对应行的：

```text
当前余额
```

如果 Excel 公式缓存为空，客户端应按以下公式自行计算：

```text
今日余额 = 截止上传日期累计收款 - 截止上传日期累计快递费用 - 截止上传日期累计异常扣款
```

### 状态

```text
今日余额 < 0  -> 欠款
今日余额 >= 0 -> 充足
```

## 上传数据结构

客户端点击 `确认并上传` 后，向接收端发送 JSON：

```json
{
  "appVersion": "8.10.0",
  "uploadDate": "2026-06-01",
  "uploadedAt": "2026-06-01 12:00:00",
  "sourceDir": "/Users/beetle/Desktop/express/客户每日快递费明细",
  "records": [
    {
      "customer": "余小姐",
      "todayFee": 5537.0,
      "todayBalance": -2180.0,
      "status": "欠款"
    }
  ]
}
```

## 客户端模块设计

### 核心模块

建议新增：

```text
app/express_app/core/balance_upload.py
```

职责：

1. 扫描客户每日明细目录。
2. 读取每个客户的历史汇总表。
3. 根据上传日期生成上传预览数据。
4. 生成 JSON payload。
5. 调用上传接口。

建议数据结构：

```python
@dataclass(frozen=True)
class BalanceUploadRecord:
    customer: str
    today_fee: float
    today_balance: float
    status: str


@dataclass(frozen=True)
class BalanceUploadPreview:
    upload_date: date
    source_dir: Path
    records: list[BalanceUploadRecord]
    errors: list[str]

    @property
    def customer_count(self) -> int: ...

    @property
    def total_today_fee(self) -> float: ...

    @property
    def total_today_balance(self) -> float: ...

    @property
    def debtor_count(self) -> int: ...
```

## 接收端配置

不建议把接口配置放在 `余额上传` 页面里，避免用户每次上传时看到技术配置。

建议放到 `系统设置`：

```text
上传接口地址
上传密钥
```

客户端请求时使用：

```http
POST /api/balance-upload
Authorization: Bearer <上传密钥>
Content-Type: application/json
```

## 交互规则

1. 页面打开时默认上传日期为当天。
2. 用户点击 `读取数据` 后生成预览。
3. 预览为空时，禁用 `确认并上传`。
4. 用户未勾选确认时，禁用 `确认并上传`。
5. 上传中禁用按钮，避免重复提交。
6. 上传成功后显示成功日志。
7. 上传失败后显示失败原因，但不改变本地文件。

## 错误处理

需要展示但不中断整个流程的错误：

```text
客户目录不存在
某客户缺少历史汇总表
某客户历史汇总缺少指定日期
某客户历史汇总缺少必要列
接口地址为空
上传密钥为空
网络超时
服务器返回非 2xx
```

如果部分客户读取失败，页面仍展示可读取客户，并在日志中提示失败客户数量。

## 安全要求

1. 正式使用必须走 HTTPS。
2. 必须携带上传密钥。
3. 上传密钥不显示在余额上传页面。
4. 上传前必须由用户确认日期。
5. 上传 payload 不包含本地文件明细、运单号、地址、联系人等敏感明细字段。
6. 上传失败不重试无限次，避免重复提交。

## 后续可扩展

第一版只做手动上传。

后续如果需要，可以再扩展：

```text
上传历史记录
自动定时上传
上传成功后服务端回执
接收端后台看板
按客户筛选上传
```

这些都不放在第一版，避免影响主流程稳定性。
