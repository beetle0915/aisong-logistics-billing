# 艾松运费管家 V8.6.1 运行前轻量测试优化 PRD

## 背景

V8.6.0 新增了 `开始测试`，用于在正式计算前发现输入问题，避免生成结果和刷新历史汇总时出现半成功数据。实际使用中，约 8000 行销售表的测试速度偏慢，原因是旧测试接近一次完整干跑：逐行查找省份报价、解析计费模板，甚至覆盖了正式计算阶段才必须做的完整报价匹配。

V8.6.1 将 `开始测试` 调整为轻量输入健康检查，让用户更快知道“现在能不能进入正式计算”。

## 目标

1. 版本升级为 `V8.6.1`。
2. 点击 `开始测试` 后立即进入 `费用计算 / 运行`，让用户看到测试日志。
3. 测试阶段只做必要输入检查，不生成总结果、不生成客户每日明细、不刷新客户历史汇总。
4. 测试阶段不再逐行做省份报价匹配，不计算费用，不检查正式计算才会触发的每条记录报价结果。
5. 测试通过后才解锁 `开始计算`。
6. 报价文件发生增删改后，已通过的测试状态自动失效，需要重新测试。

## 测试范围

`开始测试` 需要检查：

- 四个核心路径是否已配置并可读取：销售出库单、报价表目录、总结果目录、客户每日明细目录。
- 销售出库单是否存在、可打开、具备必要列。
- 如果需要生成客户每日明细或客户历史汇总，销售表必须有 `出库单号`，用于历史明细去重。
- 每行关键字段是否存在且格式可用：`业务员`、`快递公司`、`省`、`重量`、`出库日期`、必要时的 `出库单号`。
- `重量` 必须是大于 0 的数字。
- `业务员` 必须能在报价目录中找到对应报价文件。
- `快递公司` 必须能通过精准映射、关键词映射或报价 sheet 名识别到标准快递公司。
- 报价表 sheet 必须具备基础表头：`省份参照列`、`首重费用`、`续重费用`。

## 非目标

- 不在测试阶段检查每个省份是否一定存在报价。
- 不在测试阶段计算快递费。
- 不在测试阶段判断大件记录是否一定能匹配到 `_大件` 省份报价。
- 不改变正式计算逻辑；正式计算仍保留完整报价匹配、费用计算和异常日志。
- 不改变客户历史汇总、客户每日明细、总结果 Excel 结构。

## UI 流程

1. 用户在 `费用计算 / 配置` 选择销售出库单。
2. 点击 `开始测试`。
3. 系统清空本次日志和结果列表，状态显示 `测试中`。
4. 页面立即切到 `费用计算 / 运行`，日志显示测试进度。
5. 测试通过：状态显示 `测试通过，等待开始计算`，`开始计算` 按钮可点击。
6. 测试未通过：仍停留 `运行` 页，日志展示问题和修改建议，`开始计算` 保持禁用。
7. 用户返回配置或系统设置修正数据后，再次点击 `开始测试`。
8. 用户修改销售表、报价表、路径或规则配置后，原测试通过状态失效，需要重新测试。

## 验收标准

1. `APP_VERSION` 为 `8.6.1`，输出后缀为 `v8_6_1`。
2. `开始测试` 对省份没有报价但其他关键输入合法的数据仍可通过，证明没有做完整省份报价匹配。
3. `开始测试` 能阻止重量非数字、重量小于等于 0、业务员缺报价文件、出库日期为空、出库单号为空等必要输入问题。
4. `开始测试` 点击后自动进入 `运行` 页，失败和异常也留在 `运行` 页看日志。
5. 报价文件内容变化后，配置签名变化，正式计算前需要重新测试。
6. 测试阶段不创建输出目录和客户每日明细目录。
7. 正式计算仍能生成总结果、客户每日明细和客户历史汇总。
