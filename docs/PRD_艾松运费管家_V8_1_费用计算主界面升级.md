# 艾松运费管家 V8.1 费用计算主界面升级 PRD

## 背景

V7.x 已经完成品牌更名、客户历史汇总、收款记录、余额公式、异常日志和快递公司映射配置等连续增强。V8.1 从 7.x 之后开始新的大版本线，重点从功能补充转向主工作流体验升级。

当前桌面端主流程仍以传统表单和按钮堆叠为主。V8.1 计划接入 head 风格的「费用计算」主流程，让用户进入软件后可以更清晰地完成配置、运行、查看日志和打开结果。

## 目标

1. 版本线进入 `V8.1`，作为 7.x 之后的新大版本 UI 升级起点。
2. 主界面接入 head 风格的「费用计算」工作台。
3. 保留现有费用计算、客户每日明细、客户历史汇总等按钮能力。
4. 让左侧导航、标题栏、配置区域、运行日志区域和结果区域形成稳定布局。
5. 本次只升级主流程 UI，不改变计费规则、输出字段、配置文件格式和历史汇总逻辑。

## 范围

### 本次包含

- 主界面显示 `V8.1` 版本标识。
- 新增或改造左侧导航，当前主流程入口为 `费用计算`。
- 新增或改造顶部标题栏，明确当前页面为费用计算主流程。
- 主流程内容区包含：
  - 配置区域：销售出库单、报价目录、输出目录、客户每日明细目录、生成选项和规则配置入口。
  - 运行日志区域：承载原有日志输出和异常提示。
  - 结果区域：承载运行结果摘要、输出文件入口和打开目录能力。
- 保留原有按钮能力，包括选择文件/目录、规则配置、开始计算、打开输出目录、打开客户每日明细目录等已有主流程操作。
- 保留现有测试入口和打包自检要求，确保 UI 改造不破坏可运行性。

### 本次不包含

- 不改变任何快递费计算规则。
- 不改变顺丰、德邦大件规则。
- 不改变快递公司映射规则和配置 JSON 结构。
- 不改变客户每日明细、客户历史汇总、收款记录和余额公式逻辑。
- 不新增完整的账户余额页面。
- 不新增完整的报价预览页面。
- 不新增完整的客户档案页面。
- 不新增完整的系统设置页面。
- 不调整应用版本号文件；应用版本号由主集成负责统一修改。

```text
左侧导航

  系统设置（占位或后续版本）

顶部标题栏
  艾松运费管家 V8.1
  费用计算

费用计算主内容
  配置区域
  运行日志区域
  结果区域
```

占位导航项如需出现，应避免进入完整页面建设；本版本只保证 `费用计算` 主流程可用。

## 交互要求

1. 用户可以像 V7.x 一样完成销售出库单选择、报价目录选择、输出目录选择和客户每日明细目录选择。
2. 用户可以像 V7.x 一样开启或关闭生成总结果、客户每日明细和客户历史汇总等生成选项。
3. 用户可以继续进入规则配置，维护快递公司映射和大件规则。
4. 用户点击开始计算后，运行日志区域持续显示原有日志和错误建议。
5. 计算完成后，结果区域应提供可见反馈，并保留打开输出目录、打开客户每日明细目录等能力。
6. UI 改造不得吞掉原有异常提示，不得让失败状态只停留在控制台或隐藏日志中。

## 非目标

1. 不通过本版本重构计费核心模块。
2. 不新增数据库、账号体系或云端同步能力。
3. 不把账户余额、报价预览、客户档案、系统设置做成完整可交互业务页面。
4. 不改变 Windows 或 macOS 打包产物名称规范，除非主集成另行要求。

## 验收标准

1. 主界面可见版本号为 `V8.1`。
2. 主界面包含左侧导航，且 `费用计算` 是当前主流程入口。
3. 主界面包含标题栏，能表达当前页面是费用计算流程。
4. 主内容区包含配置区域、运行日志区域和结果区域。
5. 原有按钮能力保留：选择销售出库单、选择报价目录、选择输出目录、选择客户每日明细目录、规则配置、开始计算、打开输出目录、打开客户每日明细目录。
6. 费用计算结果与 V7.x 保持一致，不因 UI 改造改变计费规则或输出字段。
7. 不出现账户余额、报价预览、客户档案、系统设置的完整业务页面实现。
8. 现有单元测试通过。
9. `python -m compileall -q app tests` 通过。
10. macOS 打包自检通过。
11. Windows 打包流程或 GitHub Actions 打包配置自检通过。
12. `git diff --check` 通过。
