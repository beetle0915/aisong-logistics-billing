# 艾松运费管家 V8.9.3 账户余额看板优化 PRD

## 背景

V8.9.2 已经把 `异常扣款记录`、`拆分账单` 和 `超大件计费档位` 合并回正式主线。账户余额页的数据层已经会把 `异常扣款记录` 计入余额：

```text
当前余额 = 累计收款 - 累计消费 - 累计异常扣款
```

但原看板只展示累计消费、累计收款和当前余额，用户无法直接看出余额差额是否来自异常扣款。财务核对时，这会让页面看起来“算不平”。

## 目标

1. 版本号升级为 `V8.9.3`。
2. 账户余额看板显式展示累计异常扣款。
3. 把余额大盘从单一净额升级为可用余额和欠款金额两个视角。
4. 客户余额表新增 `累计异常扣款` 列。
5. 欠款客户默认置顶，并按欠款金额从大到小排序。
6. 不改变费用计算、报价预览、拆分账单、系统设置和客户历史汇总生成逻辑。

## 范围

### 本次包含

- 更新账户余额数据模型，返回每个客户的 `累计异常扣款`。
- 新增看板汇总指标：
  - 累计消费总额
  - 累计收款总额
  - 累计异常扣款
  - 可用余额合计
  - 欠款金额合计
  - 欠款客户
- 更新客户余额表列：
  - 客户
  - 累计消费
  - 累计收款
  - 累计异常扣款
  - 当前余额
  - 最近日期
  - 状态
  - 文件路径
- 将账户余额 KPI 排为两行三列，避免 6 个指标挤在一行。
- 调整排序为欠款客户优先，欠款金额越大越靠前。
- 更新版本号、打包版本和测试。

### 本次不包含

- 不新增异常扣款录入页面。
- 不编辑客户历史汇总表中的 `收款记录` 或 `异常扣款记录`。
- 不新增自动监听文件变化。
- 不新增客户详情抽屉。
- 不调整费用计算金额规则。

## 数据规则

1. 累计消费仍从 `历史汇总` sheet 最后一条有效记录的 `累计快递费用` 读取。
2. 累计收款仍从 `收款记录` sheet 的 `已付金额` 列重新求和。
3. 累计异常扣款从 `异常扣款记录` sheet 的 `额度` 列重新求和。
4. 旧客户历史汇总文件没有 `异常扣款记录` 时，累计异常扣款按 `0` 处理。
5. 当前余额使用：

```text
累计收款 - 累计消费 - 累计异常扣款
```

6. 可用余额合计只累计当前余额大于 0 的客户。
7. 欠款金额合计只累计当前余额小于 0 的客户，并以正数展示。
8. 当前余额小于 0 时，状态为 `欠款`；否则为 `充足`。

## 排序规则

1. 欠款客户排在余额充足客户前面。
2. 欠款客户按欠款金额从大到小排序。
3. 同类客户再按最近日期从新到旧排序。
4. 日期和金额都相同时按客户名排序。

## 验收标准

1. 主界面版本号显示 `V8.9.3`。
2. 账户余额 KPI 显示 6 个指标，并排成两行三列。
3. 客户余额表包含 `累计异常扣款` 列。
4. 当前余额继续扣减异常扣款。
5. 可用余额合计和欠款金额合计分别统计正余额和负余额。
6. 欠款客户默认置顶，欠款金额大的客户靠前。
7. 老客户历史汇总缺少 `异常扣款记录` 时仍可正常显示。
8. 账户余额相关单元测试通过。
9. 全量单元测试、compileall、diff check 和 macOS 打包自检通过。
