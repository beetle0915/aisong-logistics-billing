# 艾松运费管家 V8.6.0 费用计算运行前测试 PRD

## 背景

费用计算会生成总结果、客户每日明细和客户历史汇总。原流程在配置页点击 `开始计算` 后直接进入正式运行，如果销售表或报价表存在输入问题，任务可能在中途才暴露异常，增加结果文件和历史汇总被半成功数据污染的风险。

## 目标

1. 版本升级为 `V8.6.0`。
2. 费用计算配置页主动作改为 `开始测试`。
3. `开始测试` 只读验证输入数据和报价匹配，不生成总结果、不生成客户每日明细、不刷新客户历史汇总。
4. 测试通过后自动进入 `运行` 页，并解锁 `开始计算`。
5. 测试未通过时停留在 `配置` 页，日志展示可修正的问题，正式计算按钮保持禁用。
6. 正式计算仍沿用原有生成逻辑和实时阶段日志。

## 验证范围

运行前测试需要覆盖：

- 销售出库单是否存在、可打开、具备必要列。
- 报价目录是否存在且包含可用 `.xlsx` 报价文件。
- 报价表 sheet 表头和价格数值是否可读取。
- 销售表每一行的业务员、快递公司、省份、重量是否可用于计费。
- 业务员是否存在对应报价文件。
- 标准快递公司、计费模板、省份报价是否能匹配。
- 顺丰、德邦等大件规则触发时，是否存在对应 `_大件` 报价模板。

## 非目标

- 不在测试阶段写入输出目录或客户目录。
- 不替代正式计算前的写入权限检查；正式计算仍保留原有可写探针。
- 不改变总结果、客户每日明细、客户历史汇总的 Excel 结构。
- 不改变 CLI 的直接计算能力。

## UI 流程

1. 用户在 `费用计算 / 配置` 选择销售出库单并确认系统设置。
2. 点击 `开始测试`。
3. 系统清空本次日志和结果列表，显示“开始运行前测试”。
4. 测试通过：状态显示 `测试通过，等待开始计算`，自动切到 `运行` 页，`开始计算` 可点击。
5. 测试失败：状态显示 `测试未通过`，停留 `配置` 页，日志展示错误详情和建议。
6. 用户修正数据后重新点击 `开始测试`。
7. 用户在 `运行` 页点击 `开始计算` 后，才正式写结果文件并刷新历史数据。

## 验收标准

1. `APP_VERSION` 为 `8.6.0`，输出后缀为 `v8_6_0`。
2. `开始测试` 对合法数据返回通过，并且不创建输出目录和客户每日明细目录。
3. `开始测试` 对重量非数字、业务员缺报价文件、大件模板缺失等问题返回失败并展示建议。
4. 未通过运行前测试时，不能直接开始正式计算。
5. 测试通过后，正式计算仍能生成结果文件和客户明细/历史汇总。
6. README、测试断言和打包版本同步到 `V8.6.0`。
