# V8.9.2 完整版本线修复和超大件计费：新功能和差异说明

## 一句话总结

V8.9.2 修正了 V8.8.2 之后的版本线，正式版本完整包含 `异常扣款记录`、`拆分账单` 和 `超大件计费档位`。同时把原来固定按 `1kg` 首重计算的逻辑，升级为按 `普通件 / 大件 / 超大件` 三个计费档位计算。报价表仍然保持三列不变，但系统会根据档位使用不同的首重重量。

## 新增功能

### 1. 修正版本线，恢复完整功能

V8.9.2 的正式发布链路为：

```text
V8.8.2
→ V8.8.3 异常扣款记录
→ V8.9.0 拆分账单
→ V8.9.1 超大件计费档位
→ V8.9.2 完整发布
```

因此 V8.9.2 同时包含：

| 功能 | 状态 |
| --- | --- |
| `异常扣款记录` | 已恢复，客户历史汇总会自动生成并保留该 sheet |
| `拆分账单` | 已保留，导航入口在 `报价预览` 和 `系统设置` 之间 |
| `应付金额` 汇总 | 已保留，拆分结果每个 sheet 顶部展示该客户应付金额 |
| `超大件计费` | 已升级为 V8.9.2 正式功能 |

### 2. 新增超大件计费档位

默认超大件规则：

| 配置项 | 默认值 |
| --- | --- |
| 超大件快递 | `顺丰`、`德邦` |
| 超大件首重重量 | `60kg` |
| 超大件模板后缀 | `_超大件` |

当标准快递公司为 `顺丰` 或 `德邦`，并且重量 `>= 60kg` 时，系统会使用：

```text
顺丰_超大件
德邦_超大件
```

对应业务员报价表中需要新增这些 sheet，sheet 内仍然只需要：

```text
省份参照列
首重费用
续重费用
```

### 3. 大件首重逻辑修正

旧逻辑里，大件虽然切到了 `顺丰_大件` 或 `德邦_大件` sheet，但续重重量仍然按 `重量 - 1kg` 算。

新逻辑里，大件的首重重量默认是 `20kg`。也就是说：

```text
22kg 大件
续重重量 = ceil(22 - 20) = 2
快递费用 = 大件首重费用 + 2 * 大件续重费用
```

这更符合“大件 sheet 的首重费用代表 20kg 内价格”的业务含义。

### 4. 结果表新增复核字段

销售出库单计算结果会新增这些字段：

```text
首重重量
计费档位
计费模板
```

用途：

| 字段 | 用途 |
| --- | --- |
| `首重重量` | 看这条记录按多少 kg 作为首重 |
| `计费档位` | 显示 `普通件`、`大件` 或 `超大件` |
| `计费模板` | 显示实际使用的报价 sheet，例如 `顺丰_超大件` |

这些字段用于复核，不改变原有 `快递费用` 字段的名称。

### 5. 系统设置新增超大件配置

`系统设置 -> 大件规则` 中新增：

```text
超大件快递
超大件首重重量
超大件模板后缀
```

保存时会校验：

1. 大件首重重量必须大于 0。
2. 超大件首重重量必须大于 0。
3. 超大件首重重量必须大于大件首重重量。
4. 大件和超大件快递公司不能为空。
5. 大件和超大件模板后缀不能为空。

## 新旧逻辑差异

### 计费档位差异

| 重量范围 | 旧逻辑 | 新逻辑 |
| --- | --- | --- |
| `< 20kg` | 普通模板，按 1kg 首重 | 普通模板，按 1kg 首重 |
| `>= 20kg 且 < 60kg` | 大件模板，但仍按 1kg 首重 | 大件模板，按 20kg 首重 |
| `>= 60kg` | 大件模板，仍按 1kg 首重 | 超大件模板，按 60kg 首重 |

### 续重重量差异

| 示例 | 旧逻辑续重重量 | 新逻辑续重重量 |
| --- | ---: | ---: |
| 顺丰 2.3kg | `ceil(2.3 - 1) = 2` | `ceil(2.3 - 1) = 2` |
| 顺丰 20kg | `ceil(20 - 1) = 19` | `0` |
| 顺丰 22kg | `ceil(22 - 1) = 21` | `ceil(22 - 20) = 2` |
| 顺丰 60kg | `ceil(60 - 1) = 59` | `0` |
| 顺丰 65kg | `ceil(65 - 1) = 64` | `ceil(65 - 60) = 5` |

### 费用示例差异

假设报价如下：

```text
顺丰_大件：首重费用 30，续重费用 5
顺丰_超大件：首重费用 80，续重费用 8
```

| 记录 | 旧逻辑 | 新逻辑 |
| --- | --- | --- |
| 顺丰 22kg | `30 + 21 * 5 = 135` | `30 + 2 * 5 = 40` |
| 顺丰 65kg | 旧逻辑没有超大件，会走大件：`30 + 64 * 5 = 350` | `80 + 5 * 8 = 120` |

## 对旧数据的影响

### 已生成的客户每日明细

旧的【客户每日快递费明细】可以继续使用。旧文件没有 `首重重量`、`计费档位`、`计费模板` 字段，不会导致历史汇总失败。

刷新客户历史汇总时，系统仍然只强制依赖这些老字段：

```text
出库日期
业务员
重量
快递费用
快递公司（标准版）
```

### 历史汇总中的快递明细

如果历史汇总同时读到旧每日明细和新每日明细：

| 文件类型 | 新增字段表现 |
| --- | --- |
| 旧每日明细 | `首重重量`、`计费档位`、`计费模板` 为空 |
| 新每日明细 | 正常写入 `首重重量`、`计费档位`、`计费模板` |

系统会自动合并表头，不会因为旧文件缺列而丢数据。

### 需要注意的情况

如果只是继续跑新销售表，旧记录不会被改动。

如果重新拿以前的销售出库单再跑一次计算，系统会按 V8.9.2 新规则重新生成对应日期的客户每日明细。这样可能覆盖旧口径金额。重跑历史销售表前，建议先备份：

```text
客户每日快递费明细
输出结果
```

## 报价表需要补充的内容

如果 `顺丰`、`德邦` 存在 60kg 及以上订单，对应业务员报价表需要新增：

```text
顺丰_超大件
德邦_超大件
```

如果缺少超大件 sheet，运行日志会提示：

```text
缺少超大件报价模板：顺丰_超大件
请在对应业务员报价表中新增 sheet，并填写省份、首重费用、续重费用。
```
