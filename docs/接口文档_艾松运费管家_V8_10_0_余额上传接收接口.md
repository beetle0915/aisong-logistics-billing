# 艾松运费管家 V8.10.0 余额上传接收接口文档

## 1. 接口用途

接收 `艾松运费管家` 客户端上传的指定日期客户余额快照。客户端会在用户确认上传日期后，将每个客户的 `今日快递费消费`、`今日余额`、`余额日期` 和 `状态` 发送给接收侧。

该接口用于接收汇总数据，不接收快递明细、运单号、地址、联系人等敏感明细。

## 2. 请求信息

```http
POST <上传接口地址>
Authorization: Bearer <上传密钥>
Content-Type: application/json
```

示例路径由接收侧自行决定，例如：

```http
POST /api/express-balance/upload
```

客户端配置位置：

```text
系统设置 > 余额上传 > 上传接口地址 / 上传密钥
```

## 3. 鉴权

客户端通过 Bearer Token 传递上传密钥：

```http
Authorization: Bearer secret-token
```

接收侧建议：

1. 校验 `Authorization` 是否存在。
2. 校验格式是否为 `Bearer <token>`。
3. 校验 token 是否与服务端配置一致。
4. token 错误时返回 `401`。

## 4. 请求体 JSON

### 示例

```json
{
  "schemaVersion": "1.0",
  "appVersion": "8.10.0",
  "uploadDate": "2026-06-01",
  "uploadedAt": "2026-06-01T13:30:00",
  "sourceDir": "/Users/beetle/Desktop/express/客户每日快递费明细",
  "summary": {
    "customerCount": 2,
    "totalTodayFee": 120.0,
    "totalTodayBalance": 250.0,
    "debtorCount": 1
  },
  "records": [
    {
      "customer": "客户A",
      "todayFee": 120.0,
      "todayBalance": 300.0,
      "balanceDate": "2026-06-01",
      "status": "充足"
    },
    {
      "customer": "客户B",
      "todayFee": 0.0,
      "todayBalance": -50.0,
      "balanceDate": "2026-05-28",
      "status": "欠款"
    }
  ]
}
```

## 5. 字段说明

### 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---:|---:|---|
| `schemaVersion` | string | 是 | 当前固定为 `1.0`，用于后续接口兼容 |
| `appVersion` | string | 是 | 客户端版本，例如 `8.10.0` |
| `uploadDate` | string | 是 | 用户确认上传的数据日期，格式 `YYYY-MM-DD` |
| `uploadedAt` | string | 是 | 客户端发起上传的本地时间，ISO 格式，例如 `2026-06-01T13:30:00` |
| `sourceDir` | string | 是 | 客户端本地客户明细目录，仅用于排查来源，可不展示给最终用户 |
| `summary` | object | 是 | 本次上传汇总 |
| `records` | array | 是 | 客户余额记录列表 |

### summary 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---:|---:|---|
| `customerCount` | number | 是 | 本次上传客户数量 |
| `totalTodayFee` | number | 是 | 本次上传客户的今日快递费消费合计 |
| `totalTodayBalance` | number | 是 | 本次上传客户的今日余额合计 |
| `debtorCount` | number | 是 | 今日余额小于 0 的客户数量 |

### records 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---:|---:|---|
| `customer` | string | 是 | 客户名称 |
| `todayFee` | number | 是 | 上传日期当天快递费消费。当天无发货时为 `0.0` |
| `todayBalance` | number | 是 | 截止上传日期的客户余额 |
| `balanceDate` | string | 是 | 余额取数日期，格式 `YYYY-MM-DD` |
| `status` | string | 是 | `充足` 或 `欠款` |

## 6. 业务口径

### uploadDate

`uploadDate` 是用户在客户端确认的数据日期，例如上传 `2026-06-01` 的客户余额快照。

### todayFee

如果客户在 `uploadDate` 当天有发货记录：

```text
todayFee = 当天快递费消费
```

如果客户在 `uploadDate` 当天没有发货记录：

```text
todayFee = 0.0
```

### todayBalance

`todayBalance` 表示截止 `uploadDate` 的客户余额。

客户端计算口径：

```text
todayBalance = 截止上传日期累计收款 - 最近一条累计快递费用 - 截止上传日期累计异常扣款
```

其中 `最近一条累计快递费用` 的取数规则：

```text
历史汇总中 日期 <= uploadDate 的最后一条记录
```

### balanceDate

`balanceDate` 是余额计算所使用的历史记录日期。

示例：

| 场景 | uploadDate | 客户最近发货日期 | todayFee | balanceDate |
|---|---|---|---:|---|
| 当天有发货 | `2026-06-01` | `2026-06-01` | `120.0` | `2026-06-01` |
| 当天无发货 | `2026-06-01` | `2026-05-28` | `0.0` | `2026-05-28` |

接收侧展示时，建议保留 `balanceDate`，方便运营判断该客户余额是当天更新还是沿用最近历史记录。

### status

客户端已按余额计算状态：

```text
todayBalance < 0  -> 欠款
todayBalance >= 0 -> 充足
```

接收侧可以直接使用，也可以按 `todayBalance` 再校验一次。

## 7. 幂等建议

接收侧建议按以下键做幂等覆盖：

```text
uploadDate + customer
```

同一个客户同一个 `uploadDate` 重复上传时，建议以后一次上传为准，覆盖该客户当天快照。

如果接收侧要记录上传批次，可额外保存：

```text
uploadDate + uploadedAt + appVersion
```

但业务查询余额时，建议以 `uploadDate + customer` 的最新记录为准。

## 8. 响应格式

客户端当前只判断 HTTP 状态码：

```text
2xx -> 上传成功
非 2xx -> 上传失败
```

建议接收侧返回 JSON，便于后续扩展。

### 成功响应

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{
  "ok": true,
  "message": "received",
  "received": 2
}
```

### 失败响应

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json
```

```json
{
  "ok": false,
  "message": "records is required"
}
```

## 9. 推荐错误码

| HTTP 状态码 | 场景 |
|---:|---|
| `200` 或 `201` | 接收成功 |
| `400` | JSON 格式错误、字段缺失、字段类型错误 |
| `401` | 上传密钥缺失或错误 |
| `413` | 请求体过大 |
| `429` | 请求过于频繁 |
| `500` | 服务端内部错误 |

## 10. 接收侧校验建议

接收侧建议至少校验：

1. `schemaVersion` 是否为支持版本。
2. `uploadDate` 是否为 `YYYY-MM-DD`。
3. `records` 是否为数组。
4. 每条记录的 `customer` 是否为空。
5. `todayFee`、`todayBalance` 是否为数字。
6. `balanceDate` 是否为 `YYYY-MM-DD`。
7. `status` 是否为 `充足` 或 `欠款`。
8. `summary.customerCount` 是否等于 `records.length`。

## 11. 注意事项

1. `sourceDir` 是客户端本地路径，接收侧不要依赖它作为业务主键。
2. 金额字段用数字传输，接收侧不要按字符串解析金额符号。
3. 客户当天没有发货时，仍然会上传一条记录，`todayFee = 0.0`，`balanceDate` 为最近历史记录日期。
4. 当前接口为客户端手动点击上传触发，不是自动定时同步。
