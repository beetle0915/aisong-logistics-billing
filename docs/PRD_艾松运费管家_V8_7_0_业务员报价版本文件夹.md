# 艾松运费管家 V8.7.0 业务员报价版本文件夹 PRD

## 背景

业务员报价会随时间调整。旧版本只读取报价目录中的当前报价表，历史明细中也没有记录当时使用的报价版本。后续复核历史费用或补跑旧销售表时，容易出现“现在的报价表已经变了，无法解释当时为什么这么算”的问题。

V8.7.0 约定由使用者自行维护业务员报价文件夹，系统负责读取、按出库日期选择生效报价，并在明细中留下报价版本信息。

## 目录约定

报价目录支持新格式：

```text
快递报价表/
  张三/
    20260501张三-快递报价.xlsx
    20260503张三-快递报价.xlsx
  李四/
    20260502李四-快递报价.xlsx
```

规则：

1. 文件夹名必须等于销售表中的 `业务员`。
2. 报价文件名前 8 位为 `YYYYMMDD`，即报价版本。
3. 报价生效日期由前 8 位转换为 `YYYY-MM-DD`。
4. 报价文件仍保持原 sheet 结构：`顺丰`、`顺丰_大件`、`申通`、`德邦`、`德邦_大件` 等。
5. 报价 sheet 表头仍为 `省份参照列`、`首重费用`、`续重费用`。

旧格式继续兼容：

```text
快递报价表/
  张三-快递报价.xlsx
```

如果同时存在 `快递报价表/张三/` 文件夹和顶层 `张三-快递报价.xlsx`，系统优先使用文件夹内的版本报价。

## 计算规则

每一条销售记录按：

```text
业务员 + 出库日期
```

选择报价版本。

选择规则：

```text
选择该业务员文件夹中，报价生效日期 <= 出库日期 的最新报价表
```

如果找不到可用报价版本，则该行计算失败，日志提示补充出库日期当天或更早日期的业务员报价版本。

## 新增明细字段

总结果、业务员每日明细、客户历史汇总中的 `快递明细` 都新增：

```text
报价版本
报价生效日期
```

旧顶层报价文件没有版本信息，因此这两列为空。

旧历史明细升级规则：

1. 刷新历史汇总时自动补充新表头。
2. 旧行的 `报价版本`、`报价生效日期` 为空。
3. 新计算记录写入报价版本和报价生效日期。
4. 同一 `出库单号 + 出库日期` 被重新计算覆盖时，使用新记录中的报价版本信息。

## 运行前测试

`开始测试` 仍保持轻量，不计算金额、不生成文件。

需要检查：

- 销售表中的业务员是否有对应报价文件夹或旧顶层报价表。
- 报价文件名前 8 位是否为合法日期。
- 同一业务员同一天是否存在重复报价版本。
- 每条销售记录是否能按 `业务员 + 出库日期` 找到可用报价版本。
- 找到的报价版本里是否有对应快递公司模板 sheet。
- 重量、出库日期、业务员、快递公司、省份等关键字段是否合法。

不检查：

- 不逐行匹配省份报价。
- 不计算快递费用。
- 不生成结果文件。
- 不刷新历史汇总。

## 性能约束

实现必须满足：

- 只加载本次销售表涉及到的业务员。
- 只加载本次日期范围可能用到的报价版本。
- 每个实际参与计算的报价文件最多打开一次。
- 同一个 `业务员 + 出库日期` 的版本选择结果做缓存。
- 禁止逐行打开报价文件。

## 报价预览

报价预览需要能识别业务员文件夹中的版本报价。当前版本先按业务员列出所有识别到的版本报价，后续可继续增强为显式版本下拉。

## 验收标准

1. `APP_VERSION` 为 `8.7.0`，输出后缀为 `v8_7_0`。
2. `快递报价表/业务员/YYYYMMDD业务员-快递报价.xlsx` 能按出库日期自动选中最新生效版本。
3. 旧顶层 `业务员-快递报价.xlsx` 继续可用，且报价版本字段为空。
4. 总结果、每日明细、历史 `快递明细` 写入 `报价版本` 和 `报价生效日期`。
5. 旧历史明细刷新后自动补列，旧行为空，新行有值。
6. `开始测试` 能发现缺失可用报价版本、重复报价版本和模板缺失。
7. 报价预览能识别业务员文件夹中的多个版本报价。
