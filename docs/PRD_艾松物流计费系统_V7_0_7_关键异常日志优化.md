# 艾松物流计费系统 V7.0.7 关键异常日志优化 PRD

## 背景

运行日志是用户排查数据和报价问题的主要入口。旧版本能够提示任务失败，但部分错误只显示技术原因或简短文本，用户需要反复猜测该检查哪个文件、哪个 sheet、哪一列或哪一行。

V7.0.7 聚焦 5 类高频问题，优先让日志明确说明问题位置、原因和可执行建议。

## 目标

1. 报价目录为空时，明确提示目录没有可用的 `.xlsx` 报价文件，并建议重新选择报价目录。
2. 销售表缺必要列时，显示缺失列和当前识别到的列。
3. 重量不是数字时，显示行号、重量原值和修改建议。
4. 找不到报价时，显示业务员、计费模板、省份、重量和建议检查的 sheet。
5. 大件模板缺失时，明确提示缺少 `顺丰_大件` 或 `德邦_大件`，并建议新增对应 sheet。

## 非目标

1. 不改变快递费计算规则。
2. 不改变 Excel 输出字段结构。
3. 不重做 GUI 布局。
4. 不新增远程日志上传。
5. 不在本版本新增自动保存日志文件能力。

## 日志格式

关键异常使用统一块格式：

```text
[异常类型]
阶段：...
位置：...
字段：...
原因：...
建议：...
```

其中 `阶段`、`位置` 和上下文字段按异常类型补充。

## 场景设计

### 报价目录为空

日志示例：

```text
[报价表错误]
阶段：读取报价表
位置：/Users/beetle/Desktop/express/快递报价表
报价目录：/Users/beetle/Desktop/express/快递报价表
原因：目录中没有找到可用的 .xlsx 报价文件。
建议：请重新选择报价表目录，确认选择的是包含业务员报价 Excel 的目录。
```

### 销售表缺必要列

日志示例：

```text
[销售表结构错误]
阶段：读取销售出库单
位置：/Users/beetle/Desktop/express/原始数据表/【4.7】销售出库单.xlsx
当前识别到的列：出库日期、业务员、快递公司、省
原因：缺少必要列：重量
建议：请恢复销售出库单表头，尤其是「出库日期」「业务员」「快递公司」「省」「重量」。
```

### 重量不是数字

日志示例：

```text
[行级计算错误]
阶段：计算快递费
位置：销售表 第 2 行
行号：2
业务员：客户A
原始快递公司：顺丰
标准快递公司：顺丰
计费模板：未确定
省：广东
重量原值：abc
原因：重量不是数字：abc
建议：请将重量改为数字，例如 1、2.5、20。
```

### 找不到报价

日志示例：

```text
[报价表错误]
阶段：匹配报价
位置：销售表 第 2 行
业务员：客户A
原始快递公司：顺丰
标准快递公司：顺丰
计费模板：顺丰
省：广东
重量：2.5
原因：找不到对应报价。
建议：请检查 客户A 的报价表中是否存在 sheet「顺丰」，并确认其中有「广东」的首重和续重价格。
```

### 大件模板缺失

日志示例：

```text
[报价表错误]
阶段：匹配报价
位置：销售表 第 2 行
业务员：客户A
原始快递公司：顺丰
标准快递公司：顺丰
计费模板：顺丰_大件
省：广东
重量：20
原因：缺少大件报价模板：顺丰_大件
建议：请在 客户A 的报价表中新增 sheet「顺丰_大件」，并填写「广东」的首重和续重价格。
```

## 验收标准

1. 报价目录为空的测试日志包含 `[报价表错误]`、`.xlsx` 和重新选择报价目录建议。
2. 销售表缺列的测试日志包含 `[销售表结构错误]`、缺失列和当前识别到的列。
3. 重量非数字的测试日志包含 `[行级计算错误]`、行号、重量原值和数字格式建议。
4. 找不到报价的测试日志包含业务员、计费模板、省、重量和建议检查的 sheet。
5. 大件模板缺失的测试日志包含 `顺丰_大件` 或 `德邦_大件`，并建议新增对应 sheet。
6. V7.0.5 和 V7.0.6 的客户历史汇总相关测试继续通过。
7. 版本号升级为 `V7.0.7`。
