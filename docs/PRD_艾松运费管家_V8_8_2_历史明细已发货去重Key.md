# 艾松运费管家 V8.8.2 历史明细已发货去重 Key PRD

## 背景

客户历史汇总表的 `快递明细` sheet 通过隐藏列 `历史记录Key` 实现增量覆盖。原规则使用 `出库单号 + 出库日期时间` 作为唯一 Key。

实际使用中，用户会在历史明细中手动登记退货、换货等记录。这些记录可能和原发货记录拥有相同的出库单号和出库日期时间，但 `已发货` 字段内容不同。如果继续使用两段 Key，后续刷新历史汇总时，正常发货记录可能覆盖手工登记的退货/换货记录。

## 目标

1. 将历史明细唯一 Key 调整为 `出库单号 + 出库日期时间 + 已发货`。
2. 同一出库单号、同一出库日期时间，但 `已发货` 内容不同的记录应同时保留。
3. 同一出库单号、同一出库日期时间、同一 `已发货` 内容的记录仍按后到覆盖前到。
4. 兼容旧每日明细和旧历史汇总。缺少 `已发货` 列时不报错，第三段按空值处理。
5. 刷新旧历史汇总时，优先用可见列重新生成三段 Key，避免继续沿用旧隐藏两段 Key 导致手工记录被覆盖。

## 实现范围

- 新增 `已发货` 字段常量。
- `build_historical_detail_key()` 支持第三个可选参数。
- 读取旧历史明细时，如果可见列存在 `出库单号` 和 `出库日期`，优先用可见列重新生成新 Key；存在 `已发货` 列则纳入 Key。
- 读取每日明细时，如果存在 `已发货` 列，则纳入 Key；不存在则兼容为空。
- 更新版本号为 `8.8.2`，输出后缀为 `v8_8_2`。

## 验收标准

1. 同一出库单号和出库日期时间下，`已发货=是` 与 `已发货=退货/换货` 在历史明细中保留两行。
2. 旧隐藏 Key 为两段的手动退货/换货记录，刷新后迁移为三段 Key，并不会被正常发货记录覆盖。
3. 旧每日明细缺少 `已发货` 列时仍能刷新历史汇总。
4. 客户历史汇总、报价版本和品牌版本测试通过。
