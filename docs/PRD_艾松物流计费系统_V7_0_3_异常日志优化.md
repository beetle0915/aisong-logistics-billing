# 艾松物流计费系统 V7.0.3 异常日志优化 PRD

## 背景

V7.0.2 已修复底部目录按钮在 Windows exe 中失效的问题。当前系统在路径校验、报价读取、销售表计算、客户拆分和历史汇总中已经能捕获部分异常，但异常展示仍偏技术化或过于简短。例如用户看到 `运行失败：xxx` 时，往往不知道是哪个文件、哪一列、哪一行、哪个报价模板或哪个目录导致的。

V7.0.3 的重点是提升异常日志的可读性和可操作性，让用户尽量能根据日志自行修正数据或目录配置。

## 目标

1. 异常信息尽量明确到文件、sheet、列名、行号、业务员、快递模板、省份、重量或目录。
2. 每类异常尽量给出可执行的处理建议。
3. GUI 弹窗保持简洁，详细原因进入运行日志。
4. 批量处理时，单个文件失败不影响后续文件，并在汇总里明确失败文件和原因。
5. 日志格式统一，便于复制给开发者或业务人员排查。

## 非目标

- 不改快递费计算规则。
- 不改 Excel 输出字段结构。
- 不重做 UI 布局。
- 不引入远程日志上传或联网诊断。
- 不记录用户真实业务数据以外的额外隐私信息。

## 用户场景

### 场景一：报价目录选错

用户选择了一个空目录或没有 `.xlsx` 报价表的目录。

期望日志明确说明：

- 当前使用的报价目录是什么。
- 目录是否存在。
- 是否读取到 `.xlsx` 文件。
- 建议用户重新选择 `快递报价表` 目录，而不是选择上一级或空目录。

### 场景二：销售表缺少必要列

销售表表头被改名或缺失，例如缺少 `业务员`、`快递公司`、`省`、`重量`。

期望日志明确说明：

- 出错销售表文件名。
- 缺失列名。
- 当前读取到的表头。
- 建议恢复列名或检查是否选择了正确的销售出库单。

### 场景三：某一行无法计算

某一行重量为空、业务员为空、快递公司无法解析、报价表没有对应省份价格。

期望日志明确说明：

- 行号。
- 原始快递公司。
- 解析后的标准快递公司或解析失败原因。
- 业务员、计费模板、省、重量等关键上下文。
- 建议补充数据、修正规则或检查报价模板。

### 场景四：大件模板缺失

顺丰或德邦重量达到大件阈值，但报价表没有 `顺丰_大件` 或 `德邦_大件` sheet。

期望日志明确说明：

- 触发大件的行号和重量。
- 需要的报价模板名。
- 当前报价表中已有的模板名。
- 建议在对应业务员报价表中新增大件模板。

### 场景五：客户拆分或历史汇总失败

总结果已生成，但客户每日明细或历史汇总失败。

期望日志明确说明：

- 总结果文件已经生成。
- 拆分或汇总失败的客户、日期或文件。
- 失败不影响总结果文件。
- 建议检查客户明细目录权限、是否有文件被 Excel 占用、每日明细是否被手动改坏。

## 异常分类设计

### 1. 路径和权限类异常

适用范围：

- 销售表不存在。
- 报价目录不存在。
- 输出目录无法创建或写入。
- 客户明细目录无法创建或写入。
- Excel 文件被占用导致无法保存。

日志字段：

- 异常类型：路径/权限错误。
- 出错路径。
- 操作动作：读取、写入、创建目录、保存文件。
- 系统返回。
- 建议动作。

示例：

```text
[路径/权限错误]
操作：保存总结果文件
路径：D:\艾松物流\输出结果\【5.6】_销售出库单_快递费计算结果_v7_0_3.xlsx
原因：文件可能正在被 Excel 打开，或当前用户没有写入权限。
系统返回：[WinError 32] ...
建议：关闭同名 Excel 文件后重新运行；如仍失败，请重新选择一个可写的输出目录。
```

### 2. 报价表类异常

适用范围：

- 报价目录为空。
- 报价文件名无法解析业务员。
- 报价表缺少 sheet。
- 报价表缺少省份、首重、续重列。
- 报价价格不是数字。
- 某业务员缺少某快递模板或省份价格。

日志字段：

- 异常类型：报价表错误。
- 报价文件。
- 业务员。
- 模板/sheet。
- 省份。
- 建议动作。

示例：

```text
[报价表错误]
销售表：D:\数据\【5.6】_销售出库单.xlsx
行号：18
业务员：小张
计费模板：顺丰_大件
省：广东
原因：找不到报价。
建议：检查 小张 的报价表中是否存在 sheet「顺丰_大件」，并确认其中有「广东」的首重和续重价格。
```

### 3. 销售表结构类异常

适用范围：

- 销售表缺少必要列。
- 表头空白或被合并导致无法识别。
- 工作簿损坏或不是合法 Excel 文件。

日志字段：

- 异常类型：销售表结构错误。
- 销售表路径。
- 缺失列。
- 当前识别到的列。
- 建议动作。

示例：

```text
[销售表结构错误]
销售表：D:\数据\【5.6】_销售出库单.xlsx
原因：缺少必要列：业务员、重量
当前识别到的列：出库日期、客户、快递公司、省份
建议：请将表头恢复为系统要求的标准列名，尤其是「业务员」「快递公司」「省」「重量」。
```

### 4. 行级计算类异常

适用范围：

- 业务员为空。
- 快递公司为空。
- 快递公司无法解析为标准快递公司。
- 快递公司匹配到多个标准名称。
- 省为空。
- 重量为空、不是数字、<= 0。
- 找不到对应报价。

日志字段：

- 异常类型：行级计算错误。
- 行号。
- 业务员。
- 原始快递公司。
- 标准快递公司。
- 计费模板。
- 省。
- 重量。
- 原因。
- 建议动作。

示例：

```text
[行级计算错误]
行号：27
业务员：小陈
原始快递公司：SF EXPRESS
标准快递公司：顺丰
计费模板：顺丰
省：浙江
重量：abc
原因：重量不是数字。
建议：请将重量改为数字，例如 1、2.5、20。
```

### 5. 客户拆分类异常

适用范围：

- 总结果缺少 `快递明细` sheet。
- 总结果中缺少拆分必要列。
- 同一个客户每日明细包含多个日期或多个客户。
- 客户目录无法写入。

日志字段：

- 异常类型：客户拆分错误。
- 总结果文件。
- 行号或客户。
- 日期。
- 建议动作。

### 6. 历史汇总类异常

适用范围：

- 某个客户目录不存在。
- 某个每日明细文件无法读取。
- 每日明细被手动修改后结构不合法。
- 汇总表无法保存。

日志字段：

- 异常类型：历史汇总错误。
- 客户。
- 明细文件。
- 原因。
- 建议动作。

### 7. 未知异常

适用范围：

- 未被以上分类捕获的异常。

日志字段：

- 异常类型：未知错误。
- 当前阶段。
- 异常类名。
- 异常信息。
- 建议复制完整日志给开发者。

GUI 弹窗只显示：

```text
运行失败，详细原因已写入运行日志。
```

运行日志显示完整信息。

## 日志格式设计

### 顶部运行上下文

每次运行日志开头应包含：

```text
运行版本：V7.0.3
运行时间：YYYY-MM-DD HH:mm:ss
销售表数量：N
报价目录：...
输出目录：...
客户明细目录：...
```

### 单文件上下文

批量运行时，每个文件保留独立块：

```text
========== 第 1/2 个文件 ==========
销售表：...
输出文件：...
状态：成功 / 失败 / 部分成功
```

### 错误块格式

所有错误建议使用统一结构：

```text
[异常类型]
位置：...
原因：...
建议：...
系统返回：...
```

系统返回可选，只有存在底层异常时显示。

## GUI 展示设计

### 运行日志区域

运行日志显示完整异常信息，支持用户复制。

### 弹窗策略

弹窗保持简洁：

- 路径选择阶段错误：直接显示可操作的路径提示。
- 运行中失败：提示查看运行日志。
- 批量部分失败：提示任务完成但有错误，要求查看运行日志。

### 状态栏

状态栏建议值：

- `完成`
- `完成，有错误`
- `失败，查看日志`

## 实现建议

### 增加异常格式化工具

建议新增模块：

```text
app/express_app/core/error_messages.py
```

职责：

- 将异常分类。
- 输出用户友好的错误块。
- 为行级错误补充上下文。
- 为文件级异常补充建议。

建议提供函数：

```python
format_error_block(category, reason, suggestion, location=None, system_error=None)
format_row_error(row_number, context, reason, suggestion)
format_exception(stage, exc, context=None)
```

### 增强行级上下文

`process_sales_workbook` 当前只记录：

```text
第 N 行：错误原因
```

建议改为记录：

```text
[行级计算错误]
行号：N
业务员：...
原始快递公司：...
标准快递公司：...
计费模板：...
省：...
重量：...
原因：...
建议：...
```

对于尚未解析出的字段，用 `未识别` 或 `空` 标记。

### 增强报价错误

对于 `找不到报价`，应额外输出：

- 当前业务员。
- 当前计费模板。
- 当前省份。
- 当前业务员可用模板列表。
- 当前模板可用省份数量或省份列表摘要。

### 增强批量异常

`run_express_fee_batch_job` 捕获单文件异常时，不应只写：

```text
运行失败：xxx
```

应输出：

```text
[文件处理错误]
销售表：...
阶段：读取报价 / 读取销售表 / 保存结果 / 拆分客户明细 / 历史汇总
原因：...
建议：...
```

### 增加日志保存能力

建议 V7.0.3 同步输出一份日志文本文件到输出目录：

```text
输出结果/运行日志_YYYYMMDD_HHMMSS.txt
```

该能力可以让用户在打包 exe 后更方便地把问题日志发给开发者。

## 验收标准

1. 报价目录为空时，日志明确提示目录中没有 `.xlsx` 报价文件，并建议重新选择报价表目录。
2. 销售表缺少必要列时，日志显示缺失列和当前识别到的列。
3. 重量不是数字时，日志显示行号、重量原值和修改建议。
4. 找不到报价时，日志显示业务员、计费模板、省份，并建议检查对应报价表 sheet。
5. 大件模板缺失时，日志明确提示缺少 `顺丰_大件` 或 `德邦_大件`。
6. 客户拆分失败时，日志说明总结果是否已经生成，以及失败不影响总结果。
7. GUI 弹窗不再只显示技术异常堆栈，详细信息进入运行日志。
8. 批量运行中一个文件失败时，后续文件继续处理，最终汇总显示成功文件数和错误文件数。
9. 运行日志可以复制，并可在输出目录生成 `.txt` 日志文件。
