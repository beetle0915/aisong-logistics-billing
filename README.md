# 艾松运费管家

本项目是一个本地桌面工具，用于根据销售出库单、业务员、快递公司、重量、省份和快递报价表自动计算快递费用，并生成总结果、客户每日明细和客户历史汇总账本。

当前版本：`V8.2`

## 适用场景

- 每天导入一份或多份销售出库单，批量计算每单快递费用。
- 按业务员/客户拆分每日快递明细，方便对账。
- 为每个客户维护一份长期历史汇总表，包含每日消费、历史逐条快递记录、收款记录和余额公式。
- 在报价表或销售表数据异常时，通过运行日志快速定位问题。

## 核心能力

- 批量选择销售出库单，一次处理多个 Excel 文件。
- 按业务员读取对应快递报价表。
- 自动识别销售表中的原始 `快递公司`，转换成 `快递公司（标准版）`。
- 支持顺丰、德邦 20kg 以上大件模板。
- 德邦快递最终费用按整数四舍五入。
- 生成总结果 Excel，文件名自动带版本号。
- 按业务员/客户生成客户每日快递费明细。
- 自动生成客户历史汇总表，文件名带业务员/客户名称。
- 客户历史汇总表包含 `历史汇总`、`快递明细`、`收款记录` 三个 sheet。
- `收款记录` 支持人工登记付款，`历史汇总` 自动计算今日收款、累计收款和当前余额。
- 历史 `快递明细` 按 `出库单号 + 出库日期` 增量覆盖，避免重复导入。
- 运行日志对报价目录、销售表缺列、重量异常、报价匹配异常和大件模板缺失提供明确建议。
- V8.1 主界面接入 head 风格的费用计算主流程，包含左侧导航、配置、运行日志和结果区域。
- V8.2 新增主界面 `系统设置` 页面，用于维护目录、快递公司映射和大件规则。
- GUI 生成选项使用 `✅` / `□` 标识状态，避免误解。
- macOS 和 Windows 打包产物内置 `艾松运费管家` 应用图标。
- GitHub Actions 每次 push 后自动打包 Windows 版本，artifact 名称带版本号。

## 输入文件要求

### 销售出库单

销售出库单必须包含这些列：

```text
出库日期
业务员
快递公司
省
重量
```

推荐保留 `出库单号`，客户历史 `快递明细` 会使用：

```text
出库单号 + 出库日期
```

作为历史记录唯一 key，同 key 后来的记录会覆盖旧记录。

### 快递报价表

报价表按业务员维护，文件名需要能识别业务员，例如：

```text
张三-快递报价.xlsx
李四-快递报价.xlsx
```

每个报价表中的 sheet 名应对应标准快递模板，例如：

```text
顺丰
顺丰_大件
申通
德邦
德邦_大件
```

每个报价 sheet 至少包含：

```text
省份参照列
首重费用
续重费用
```

## 输出结果

### 总结果

总结果会在销售出库单基础上追加：

```text
快递费用
首重费用
续重费用
续重重量
快递公司（标准版）
```

批量运行时输出文件名示例：

```text
【4.7】销售出库单_快递费计算结果_v8_2.xlsx
```

### 客户每日明细

系统会按业务员/客户和出库日期拆分每日明细，目录结构类似：

```text
客户每日快递费明细/
  张三/
    2026-04-07_张三_快递费明细.xlsx
  李四/
    2026-04-07_李四_快递费明细.xlsx
```

### 客户历史汇总

每个客户会生成一份历史汇总表：

```text
张三_客户快递费历史汇总.xlsx
```

包含三个 sheet：

| Sheet | 用途 |
| --- | --- |
| `历史汇总` | 按日期汇总单数、重量、今日快递总消费、累计快递费用、今日收款、累计收款、当前余额 |
| `快递明细` | 累计客户历史所有逐条快递记录，按 `出库单号 + 出库日期` 去重覆盖 |
| `收款记录` | 人工登记客户付款/充值记录，供余额公式使用 |

`收款记录` 表头：

```text
支付时间
支付方式
收款人
已付金额
收款时间
```

## 规则配置

GUI 中的 `规则配置` 用来维护核心识别规则和大件计费规则。

### 快递公司映射

销售表里的快递名称经常不是报价表 sheet 名，因此系统需要映射：

```text
销售表快递名称 -> 报价表 sheet
```

精确映射示例：

```text
顺丰速运新3=顺丰
顺丰陈开专属=顺丰
申通E物流=申通
德邦快递盖子大360小泡货特惠_4=德邦
```

关键词映射用于兜底识别，例如：

```text
顺丰=顺丰
申通=申通
德邦=德邦
```

### 大件规则

默认大件规则：

```text
大件快递：顺丰、德邦
重量阈值：20kg
模板后缀：_大件
```

当标准快递公司为 `顺丰` 且重量大于等于 20kg 时，系统会使用 `顺丰_大件` 报价 sheet。德邦同理。

## 运行日志与排错

运行日志会尽量指出问题位置、原因和建议。

常见错误包括：

- 报价目录为空：提示目录中没有 `.xlsx` 报价文件，并建议重新选择报价目录。
- 销售表缺列：显示缺失列和当前识别到的列。
- 重量不是数字：显示行号、重量原值和修改建议。
- 找不到报价：显示业务员、计费模板、省份、重量，并建议检查对应 sheet。
- 大件模板缺失：提示缺少 `顺丰_大件` 或 `德邦_大件`。

## 本地运行

进入项目的 `app` 目录：

```bash
cd app
python -m express_app
```

命令行运行示例：

```bash
python -m express_app.cli \
  --sales-file /Users/beetle/Desktop/express/原始数据表/【4.7】销售出库单.xlsx \
  --price-dir /Users/beetle/Desktop/express/快递报价表 \
  --output-dir /Users/beetle/Desktop/express/输出结果 \
  --split-dir /Users/beetle/Desktop/express/客户每日快递费明细
```

## macOS 打包

```bash
cd app
python -B build_macos_app.py
```

生成：

```text
艾松运费管家.app
```

## Windows 打包

推荐使用 GitHub Actions 打包。

推送代码到 GitHub 后，进入：

```text
Actions -> Build Windows EXE
```

下载 artifact：

```text
aisong-freight-manager-v8.2-windows
```

其中包含：

```text
艾松运费管家.exe
```

## 项目结构

```text
app/
  assets/                 # 应用图标资源，供 macOS/Windows 打包使用
  express_app/
    core/                  # 计费、拆分、历史汇总核心逻辑
    gui/                   # Tkinter 桌面 GUI
    cli.py                 # 命令行入口
    version.py             # 版本号和输出文件版本后缀
  build_macos_app.py       # macOS .app 打包脚本
  build_windows_exe.py     # Windows PyInstaller 打包脚本
  windows_entry.py         # Windows GUI 入口
  requirements-windows.txt # Windows 打包依赖
docs/
  PRD_*.md                 # 各版本需求文档
  说明_当前快递费用计算逻辑.md
tests/
  test_customer_history_workbook.py
  test_error_logs.py
  test_gui_options.py
.github/workflows/
  build-windows.yml
```
